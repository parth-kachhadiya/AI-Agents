Topic-02 : Tool calling

🔷 The big idea : Model never runs anything
   • The model only writes a request saying "Call this function with given arguments", your code runs the function and sends the result back to LLM via 
     it's context memory in next call. The model never touches your code, your network or your database.

🔷 The flow is round trip with 2 API calls:
    1. You send a message + list of available tool description (Which tools are exists and their arguments).
    2. The model replies with `finish_reason : "tool_calls"` and a request instead of final answer.
    3. Your code runs the real function.
    4. You sand the whole message history again + model's request and your result.
    5. The model uses that result to generate final answer.

💡 Sample tool description schema

    tools = [
        {
            "type"     : "function",
            "function" : {
                "name"        : "get_order_status"
                "description" : "Returns the customer order status based on given Order ID"
                "parameters"  : {
                    "type"       :  "object",
                    "properties" : {
                        "order_id" : {"type" : "string", "description" : "e.g. A1203"}
                    },
                    "required"   : "order_id"
                }
            }
        }
    ]


🔷 How the model requests a tool call
    • `finish_reason` is `tool_calls`.
    • `message.content` is usually `Null`.
    • `message.tool_calls` is a list, and each item has an `id`, and `function.name` and `function.arguments`.

🔷 Tool-call ID and sending results back
    • Each request has an `ID`. When you return the result, You must attach the same ID so the model knows which request it answers. The model for 
      the second call looks like this:

      messages = [
           {"role": "user", "content": "Where is my order A1042?"},
            # the model's request, appended exactly as it came back:
           {"role": "assistant", "content": None, "tool_calls": [ ... ]},
            # your result, one message per tool call:
           {"role": "tool", "tool_call_id": "<the id from the request>", "content": "<result as a string>"},
     ]

🚨 3 Rules must remember:
    1. The assistant message with the `tool_calls` must be in history, or the API rejects your `tool` message.
    2. Every `tool_call_id` needs matching `tool` message.
    3. `content` of tool message is string. if your function returns a dictionary, you serialize it.
